# Bot — чат-бот MAX «Заявки в УК»

Node.js + TypeScript, официальная библиотека [`@maxhub/max-bot-api`](https://github.com/max-messenger/max-bot-api-client-ts).
Отдельный сервис от `backend/` (NestJS) — чтобы не конфликтовать в git с тем,
кто уже пишет бэкенд, и потому что план проекта описывает бота и бэкенд как
разные компоненты («Бот: MAX Bot API... Бэкенд внутренний, обслуживает только
бота и мини-апп»).

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` (токен от
   организаторов — **никогда не коммитьте его**, `.env` уже в `.gitignore`).
2. `npm install`
3. Узнать юзернейм бота (нужен, чтобы найти его в MAX и, возможно, для
   `MINI_APP_URL`, см. ниже): `npm run whoami`
4. Запуск в режиме разработки (long polling, перезапуск при изменениях):
   `npm run dev`

Бот работает через long polling — не нужен публичный HTTPS-адрес, чтобы
тестировать текстовые сценарии и команды. Публичный HTTPS понадобится только
для мини-аппа (см. `frontend/README.md` и раздел про MINI_APP_URL ниже).

## Что уже реализовано

- **Приветствие** (`/start` или первый запуск бота) — разное для личного
  диалога и для группового чата дома/подъезда.
- **Подача заявки текстом**: кнопка «📝 Подать заявку» → пользователь пишет
  описание проблемы → бот классифицирует категорию (та же эвристика по
  ключевым словам, что в мини-аппе) и показывает нормативный срок → кнопка
  «Оформить заявку в мини-приложении» (открывает мини-апп). Фото/адрес/
  телефон сознательно не собираются в боте — это часть формы в мини-аппе
  (план проекта, раздел 4: бот — короткие шаги, мини-апп — формы и списки).
- **Кнопка «🤫 Потише»** — в групповых чатах, анонимно постит в тот же чат
  просьбу вести себя потише. Без анти-спама (можно добавить лимит по времени).
- **Рассылка объявлений** — команда `/announce текст`, доступна только
  user_id из `ADMIN_USER_IDS`. Рассылает во все групповые чаты, где состоит
  бот (не в личные диалоги — чтобы не выглядело как спам конкретным людям).
- **Переход в панель администратора мини-аппа** — отдельная кнопка (видна
  только админам из `ADMIN_USER_IDS`), открывает мини-апп с `payload="admin"`.
- **`/notify`-эндпоинт** (`src/notifyServer.ts`) — готов принимать вызовы от
  бэкенда для проактивных уведомлений о смене статуса заявки, но **ещё не
  подключён** — см. TODO ниже.

## Что ЕЩЁ НЕ сделано / требует проверки

1. **`MINI_APP_URL` — формат не подтверждён.** Судя по описанию в PR
   [#222](https://github.com/max-messenger/max-bot-api-client-ts/pull/222)
   официального клиента, кнопка `openApp` принимает «ссылку на
   мини-приложение бота». Не удалось проверить по первоисточнику
   (`dev.max.ru` был недоступен из рабочей среды), совпадает ли это со
   ссылкой, которую вы отправляете организаторам через форму
   (https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/), или это должен
   быть deep-link вида `https://max.ru/<botUsername>?startapp=...`.
   **Перед сдачей — проверить вручную**, что кнопка реально открывает
   мини-апп, и при необходимости поправить `src/config.ts`.

2. **Панель администратора в мини-аппе не существует.** Кнопка «🛠 Панель
   администратора» уже готова в боте и передаёт `payload="admin"`, но
   фронтенд (`frontend/`) пока не читает этот payload и не имеет отдельного
   экрана редактирования заявок. Это отдельная задача на фронт.

3. **Уведомления о смене статуса не подключены.** `src/notifyServer.ts`
   поднимает HTTP-эндпоинт `POST /notify`, готовый слать сообщение
   пользователю по его MAX `user_id`, но:
   - модель заявки в `backend/` пока не хранит `max user_id` заявителя;
   - `backend/` пока не вызывает этот эндпоинт при смене статуса.

   Чтобы это заработало: при создании заявки (через бота или мини-апп)
   передавать `user_id` пользователя в бэкенд и сохранять его в заявке;
   при смене статуса бэкенду нужно сделать
   `POST http://<host бота>:${NOTIFY_PORT}/notify` с заголовком
   `X-Notify-Secret: ${NOTIFY_SECRET}` и телом `{ "userId": ..., "text": ... }`.

4. **Детали MAX Bot API собраны по типам из `node_modules/@maxhub/max-bot-api`
   и вторичным источникам** (официальная документация `dev.max.ru` была
   недоступна из рабочей среды при написании кода) — код компилируется и
   типы сходятся, но **не протестирован живым вызовом** к серверам MAX
   (сеть тоже была недоступна). Первый реальный прогон — ваша задача,
   начните с `npm run whoami`.

## Структура

```
src/
  config.ts            — переменные окружения
  data/slaConfig.ts     — справочник категорий/сроков (дублирует frontend, см. комментарий в файле)
  lib/
    classifyCategory.ts — эвристика категории по тексту (дублирует frontend)
    isAdmin.ts           — проверка user_id по ADMIN_USER_IDS
    requestDrafts.ts     — in-memory состояние диалога "подать заявку"
    getAllBotChats.ts    — постраничный сбор всех чатов бота (для /announce)
  keyboards.ts          — сборка inline-клавиатур
  handlers/
    start.ts             — приветствие (диалог/групповой чат)
    newRequest.ts         — сценарий подачи заявки текстом
    announce.ts           — /announce
    quiet.ts               — кнопка "Потише"
  notifyServer.ts        — HTTP-эндпоинт для уведомлений от бэкенда
  whoami.ts               — npm run whoami
  index.ts                — точка входа, регистрирует все обработчики
```
