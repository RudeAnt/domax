# Bot — чат-бот MAX «Заявки в УК»

Node.js + TypeScript, официальная библиотека [`@maxhub/max-bot-api`](https://github.com/max-messenger/max-bot-api-client-ts).
Отдельный сервис от `backend/` (NestJS) — чтобы не конфликтовать в git с тем,
кто уже пишет бэкенд.

Бот **не создаёт заявки** — это делает только мини-приложение. Роль бота:
уведомлять о смене статуса заявки, рассылать новости дома, давать кнопку
«Потише» и открывать мини-апп (включая отдельный вход в панель админа).

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` (токен от
   организаторов — **никогда не коммитьте его**, `.env` уже в `.gitignore`).
2. `npm install`
3. Узнать юзернейм бота: `npm run whoami` (текущий бот команды —
   `t268_hakaton_max_bot`).
4. Запуск в режиме разработки (long polling, перезапуск при изменениях):
   `npm run dev`

Если при запуске/whoami видите ошибку `unable to get local issuer certificate` —
это антивирус с проверкой HTTPS (Kaspersky/ESET/Avast и т.п.), а не проблема
кода. Временный обход для разработки (в cmd.exe, только для этого окна):

```
set NODE_TLS_REJECT_UNAUTHORIZED=0
npm run dev
```

Бот работает через long polling — не нужен публичный HTTPS-адрес, чтобы
тестировать команды и кнопки. Публичный HTTPS понадобится только для
мини-аппа (переменная `MINI_APP_URL`, см. ниже).

## Что уже реализовано

- **Приветствие** (`/start` или первый запуск бота) — разное для личного
  диалога и для группового чата дома/подъезда. Печатает в консоль
  `user_id` написавшего — оттуда берите значения для `ADMIN_USER_IDS`.
- **Кнопка «Открыть мини-приложение»** — в личном диалоге. Появляется,
  только когда заполнен `MINI_APP_URL` (пустая ссылка ломает отправку
  сообщения целиком — проверено на практике).
- **Кнопка «🛠 Панель администратора»** — отдельная от обычной кнопки
  мини-аппа, видна только user_id из `ADMIN_USER_IDS`, открывает мини-апп
  с `payload="admin"`.
- **Кнопка «🤫 Потише»** — в групповых чатах дома, анонимно постит в тот же
  чат (то есть всем жильцам этого чата) просьбу вести себя потише. Без
  анти-спама (можно добавить лимит по времени, если понадобится).
- **Рассылка новостей** — команда `/announce текст`, доступна только
  user_id из `ADMIN_USER_IDS`. Рассылает всем известным чатам (личным и
  групповым) — список бот ведёт сам, запоминая каждого, кто с ним хоть
  раз взаимодействовал (файл `bot/data/subscribers.json`, не в git).
  Пример: `/announce Завтра с 10 до 14 отключат воду в доме`.
  Официальный метод "список всех чатов бота" (GET /chats) на реальном
  сервере MAX отвечает 404 "Path /chats is not recognized" — проверено
  на практике, поэтому используется свой список вместо него
  (см. `src/lib/subscribers.ts`).
- **`/notify`-эндпоинт** (`src/notifyServer.ts`) — готов принимать вызовы от
  бэкенда для уведомлений о смене статуса заявки, но **ещё не подключён к
  бэкенду** — см. TODO ниже, это самое важное, что осталось доделать.

## Что ЕЩЁ НЕ сделано / требует проверки

1. **Уведомления о смене статуса — главное недостающее звено.**
   `src/notifyServer.ts` поднимает HTTP-эндпоинт `POST /notify`, готовый
   слать сообщение пользователю по его MAX `user_id`, но:
   - модель заявки в `backend/` пока не хранит `max user_id` заявителя;
   - `backend/` пока не вызывает этот эндпоинт при смене статуса.

   Чтобы это заработало: 1) мини-апп при создании заявки должен передать
   бэкенду `user_id` пользователя MAX (его можно получить через MAX Bridge,
   см. `frontend/src/lib/maxBridge.ts` → `getCurrentUser()`); 2) `backend/`
   сохраняет этот `user_id` в заявке; 3) при смене статуса `backend/` делает
   `POST http://<host бота>:${NOTIFY_PORT}/notify` с заголовком
   `X-Notify-Secret: ${NOTIFY_SECRET}` и телом `{ "userId": ..., "text": ... }`.
   Это отдельная задача для бэкенд-разработчика, бот со своей стороны готов.

2. **`MINI_APP_URL` — формат не подтверждён.** Судя по описанию в PR
   [#222](https://github.com/max-messenger/max-bot-api-client-ts/pull/222)
   официального клиента, кнопка `openApp` принимает «ссылку на
   мини-приложение бота» — вероятно, тот же публичный HTTPS-адрес, что вы
   отправляете организаторам через форму
   (https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/), либо deep-link
   вида `https://max.ru/<botUsername>?startapp=...`. Точно не подтверждено —
   `dev.max.ru` был недоступен при написании кода. Как только фронтенд
   будет выложен на публичный адрес, впишите его в `bot/.env` в
   `MINI_APP_URL` и проверьте, что кнопка реально открывает мини-апп.

3. **Панель администратора в мини-аппе ещё не существует.** Кнопка «🛠 Панель
   администратора» в боте готова и передаёт `payload="admin"`, но
   `frontend/` пока не читает этот payload и не имеет отдельного экрана
   редактирования заявок — это отдельная фронтенд-задача.

4. **Детали MAX Bot API собраны по типам из `node_modules/@maxhub/max-bot-api`**
   (официальная документация `dev.max.ru` была недоступна при написании
   кода) — код компилируется и уже проверен живым запуском (бот подключается,
   отвечает на `/start`), но не все сценарии протестированы вручную
   (в частности `/announce` и `MINI_APP_URL`).

## Как добавить администратора

1. Попросите нужного человека написать боту `/start`.
2. В окне, где запущен `npm run dev`, найдите строчку
   `[start] сообщение от user_id=...`.
3. Впишите это число в `bot/.env`, в `ADMIN_USER_IDS` (через запятую, если
   администраторов несколько), и перезапустите бота.

## Структура

```
src/
  config.ts            — переменные окружения
  lib/
    isAdmin.ts           — проверка user_id по ADMIN_USER_IDS
    getAllBotChats.ts    — постраничный сбор всех чатов бота (для /announce)
  keyboards.ts          — сборка inline-клавиатур
  handlers/
    start.ts             — приветствие (диалог/групповой чат), логирует user_id
    announce.ts           — /announce
    quiet.ts               — кнопка "Потише"
  notifyServer.ts        — HTTP-эндпоинт для уведомлений от бэкенда
  whoami.ts               — npm run whoami
  index.ts                — точка входа, регистрирует все обработчики
```
