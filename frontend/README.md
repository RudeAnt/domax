# Frontend — мини-приложение MAX «Заявки в УК»

React 18 + TypeScript + Vite. Стек выбран под `@maxhub/max-ui` — официальная
библиотека компонентов MAX доступна только для React.

## Запуск

```bash
npm install
npm run dev
```

Приложение открывается как обычный сайт в браузере — MAX Bridge (`window.WebApp`)
внутри клиента MAX отсутствует, весь код в `src/lib/maxBridge.ts` на этот случай
рассчитан и просто не выполняет вызовы к нему. Полноценно платформенное
поведение (тема, BackButton, haptics, данные пользователя) проверяется только
запуском мини-аппа внутри самого MAX.

## Что уже реализовано (MVP must-have по плану проекта)

- `/` — список заявок со статусом (Зарегистрирована/В работе/Закрыта) и
  таймером до нормативного SLA-срока (`src/components/SlaTimer.tsx`).
- `/new` — форма подачи заявки: описание, категория (с эвристикой
  автоклассификации по ключевым словам, `src/utils/classifyCategory.ts`),
  адрес, телефон, фото.
- `/requests/:id` — карточка заявки; при просрочке — кнопка с готовым
  текстом обращения в жилищную инспекцию/ГИС ЖКХ (платформенный бонус
  из стратегии, раздел 4).

## Данные и бэкенд

Бэкенд (NestJS) пока не отдаёт домен-эндпоинты заявок. Чтобы не блокироваться,
весь доступ к данным идёт через интерфейс `RequestsApi`
(`src/api/requestsApi.ts`). Сейчас есть только `MockRequestsApi` —
хранит заявки в `localStorage` браузера с тестовыми seed-данными.

Когда бэкенд будет готов:

1. Согласовать поля с `src/types/request.ts` (или наоборот, подстроить типы
   под реальный контракт).
2. Реализовать `HttpRequestsApi implements RequestsApi`, использующую
   `fetch`/`axios` к бэкенду.
3. Поменять экспорт `requestsApi` в конце `requestsApi.ts` — остальной код
   (страницы, компоненты) трогать не нужно, он работает через интерфейс.

## Справочник нормативных сроков (SLA)

`src/data/slaConfig.ts` — **тестовые данные**, явно помечены в коде.
Часы реагирования/устранения по 5 категориям — плейсхолдер для демонстрации
механики таймера, ориентир — Постановление Правительства РФ №290. Перед
защитой сверить точные значения с первоисточником.

## Интеграция с MAX (Bridge + UI)

- `index.html` подключает `https://st.max.ru/js/max-web-app.js` — скрипт
  клиента MAX, создаёт глобальный `window.WebApp`.
- `src/lib/maxBridge.ts` — типизированная обёртка над `window.WebApp`
  (ready/expand, BackButton, HapticFeedback, данные пользователя). Каждый
  вызов defensive: если API нет или отличается от ожидаемого — приложение
  не падает, просто не получает платформенную фичу.
- `src/main.tsx` оборачивает приложение в `<MaxUI>` из `@maxhub/max-ui` —
  провайдер темы/токенов библиотеки компонентов.

**Важно:** во время разработки не было прямого доступа к
`dev.max.ru/docs/webapps/bridge` (сеть блокировала запросы), поэтому набор
методов в `maxBridge.ts` собран по вторичным источникам и примерам. Перед
финальной сдачей — свериться с официальной документацией вручную:
- https://dev.max.ru/docs/webapps/bridge
- https://dev.max.ru/docs/webapps/introduction
- https://dev.max.ru/ui

## Дизайн

Макета от дизайнера пока нет. Вся визуальная часть держится в
`src/styles/tokens.css` (CSS-переменные: цвета, радиусы, отступы) и в
`src/styles/global.css` (базовые классы `.card`, `.btn`, `.field`, `.badge`
и т.д.), а не хардкожена по компонентам. Экраны сейчас — обычная семантическая
разметка, не компоненты `@maxhub/max-ui`: точный API компонентов библиотеки
(`Button`, `Input`, `Panel` и т.д.) не удалось перепроверить по тем же причинам
недоступности документации, поэтому рискованно было завязывать на угаданные
пропсы. Когда придёт макет и/или будет время свериться с `@maxhub/max-ui`:

1. Обновить значения в `tokens.css` под реальную палитру/типографику.
2. Точечно заменить примитивы (`<button className="btn">`,
   `<div className="card">` и т.п.) на реальные компоненты `@maxhub/max-ui`
   там, где это даёт нативный вид — структура страниц и вся бизнес-логика
   меняться не должны.
